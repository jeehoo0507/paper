# 2, 4, 5절 분업

실험을 기다리는 동안 2, 4, 5절을 나눠 쓴다. 1, 3, 6, 7, 8절은 지후가 쓴다.

## 방향

> 모든 방법을 **아낀 것 / 치른 것** 두 칸에 올린다. 문헌에서는 이 표가 대부분 비어 있고, 우리는 같은 조건에서 직접 채운다.

4절은 방법이 무엇을 아끼는지 정리하고, 5절은 논문들이 아낀 것과 치른 것을 어디까지 적었는지 센다. 논문을 하나씩 소개하는 글을 쓰지 않는다.

## 축의 기준 (한 줄씩)

논문을 축에 넣을 때는 이 질문 하나로 판단한다.

| 축 | 기준 | 하위 갈래 (초안) |
|---|---|---|
| Shrink | teacher 순전파 **1회의 연산**이 줄어드는가 | 입력 토큰, 해상도, 깊이 |
| Skip | teacher를 **부르는 횟수**가 줄어드는가 | 데이터, 샘플, 학습 구간 |
| Reuse | teacher 출력을 **저장해** 같은 계산을 반복하지 않는가 | 출력 저장, 가중치·모듈 재사용(축에 둘지 미정) |
| Substitute | teacher나 학습 데이터를 **더 싼 것으로 바꾸는가** | 약한 teacher, teacher 없음, 데이터 대체 |

기준에 안 맞는 논문은 축에서 빼고 4절의 "teacher 연산을 줄이지 않는 논문"으로 옮긴다. logit 증류인지 특징 증류인지는 따지지 않는다.

## 분업 원칙: AI가 초안, 사람이 확정

표의 1차 채움, 세기, 계산, 문단 초안은 AI가 만든다. 팀원은 AI가 틀리기 쉬운 곳에 시간을 쓴다.

| AI가 틀리기 쉬운 곳 | 사람이 하는 일 |
|---|---|
| 표의 수치를 옮기며 조건을 빠뜨리거나 다른 행과 섞음 | 원문 표를 직접 열어 대조 |
| 그림, 부록, 보충자료에만 있는 값을 놓침 | 직접 확인 |
| "보고하지 않았다"를 쉽게 단정함 | 검색어로 본문과 부록을 찾아본 뒤 확정 |
| 논문 서술과 실제 구현이 다른 경우를 모름 | 공식 코드에서 무엇을 재고 무엇을 생략하는지 확인 |
| 판본에 따라 다른 수치를 구분 못 함 | 어느 판본인지 정하고 기록 |
| 애매한 논문을 그럴듯한 축에 넣음 | 위 기준으로 판단하고 이유를 적음 |
| 중요한 논문이 빠졌는지 모름 | 아는 논문, 최근 학회, 인용 관계로 찾기 |
| 축의 성질을 일반론으로 씀 | 왜 그 손실이 생기는지 자기 말로 설명 |

**확인 열**: 모든 표의 맨 오른쪽에 둔다. 비어 있으면 AI 초안이라 본문에 쓸 수 없다. 원문에서 확인한 사람이 `이름 날짜`를 적는다. 초안과 다르게 판단한 곳은 `decisions.md`에 한 줄씩 남긴다 (논문, 칸, 초안 값, 고친 값, 이유).

## 순서

1. 지후: 3절 기호표, 체크표 견본 한 줄.
2. 축 담당: [papers.md](papers.md)에서 자기 축 논문의 축과 갈래를 확정. 빼거나 옮길 논문을 정한다.
3. 전원: 5절 체크표 → 4절 방법 표와 축 문단, 2절 초안.
4. 취합 담당: 5절 집계와 발견 문단.
5. 전원: 자기 축이 아닌 축의 수치 10개를 원문과 대조.

## 규칙

상세: [CHECKLIST.md](CHECKLIST.md) · 지난 검수에서 나온 오류: [`../notes/audit/`](../notes/audit/README.md)
